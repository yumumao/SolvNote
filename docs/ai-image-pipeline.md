# 图片识别与解题流程

本版实现同题会话、流式结束修复及完整错题结果/教学展示恢复，并加入几何证据核验、人工转录修订和辅助线任务。本文区分已确认代码问题、流程改造和仍需按题目及供应商核对的效果；部署状态以实际镜像为准。

## 为什么不能简单拿ScanDex耗时作对照

ScanDex的识图转录和全文提取，与数学解题、结构化结果校验及可选复核不是相同任务。相同模型和调用顺序也不代表相同请求次数、图片大小或输出长度。错题本原有直接模式一次做识别和解题，先转录模式多一次，可选复核还会再增加一次。

已确认的具体问题是Responses安全出网层与协议读取层都曾等待EOF，收到完整完成事件仍可能等待连接关闭；本轮已改为完整事件完成即返回，并取消后续读取。不完整事件仍不作为成功答案；Chat和Gemini原有结束语义不放宽。此缺陷可能造成多余等待，但没有读取真实日志证明用户历次失败全部来自它。

## 默认同题会话

```text
图片 → 识图链 → 结构化转录
                    ↓
文字题 ───────→ 解题链（有读图能力才同时附图）
                    ├─ solved → 可选独立复核 → 本轮答案
                    ├─ needs_visual_check → 一次定向补读
                    │     ├─ 多模态解题者自己核原图
                    │     └─ 视觉链带具体问题补读，再交回原文字解题者
                    └─ needs_user → 保存并释放worker，等待用户补充
```

图片缺失、条件根本不在图中或需要人工选择时，直接问人，避免明知无效仍补读。补读后仍有疑点转人工，不默认换解题模型、不无限循环。原解题模型被停用或移出链时明确停止，不能悄悄换人。

## 几何转录与图像质量

结构化转录分为完整题干、显式条件及出处、可能可查的不确定项、缺失而必须问人的信息。点/线/圆、角度、长度、共线、平行、垂直、相切等只按题干或图上显式标注记录，不按外观猜测。

日常识图和解题使用压缩副本；保留原裁剪图用于定向补读、人工核对、恢复和保存错题。纯文字解题模型不会收到不支持的图片字段；多模态解题者同时看转录和题图。

会话内成功转录作为检查点复用。补图替换当前题图并使旧转录失效，下一次继续重新转录；人工文字修订保留在会话消息中并优先于旧转录。当前未实现跨会话图像哈希缓存或自动压缩长对话，不将这些后续优化写成已有能力。
## 结构化角标核验与人工修订

识图结果可返回编号角、顶点、两条射线和局部区域证据。对带角弧的几何题，系统会从保留的原裁剪图生成少量局部图，交给独立核验提示词重新确认弧的两端，不沿用首轮猜测；核验仍失败时进入人工修订，不继续用不确定角名解题。核验只是一项证据检查，不会凭外观比例补造题设。

人工可在完整编辑器中替换整段题目转录。替换会清空旧机器事实和不确定项，标记为用户修订，并在后续解题、追问和辅助线任务中优先使用；新图片提交后旧修订自动失效。题目、答案、解析或图片版本变化时，旧的几何核验和辅助线方案均不能静默复用。

## 效率和可观察性

- 正常图片会话至少2次调用；文字解题者补读的典型路径为识图→解题→补读→原模型解题，共4次。
- 新会话每轮默认6次尝试/600秒活动时间；回退、复核也计入。旧式短任务仍3次。人工等待不计时，续解不重置预算。
- 不默认并行调用多个AI；仅可选独立复核或明确失败回退。受理未知不自动重发，避免重复收费。
- 每步显示实际模型/连接、阶段、是否附图、耗时、状态、具体补读问题与人工确认。不展示内部思维链；相关私有内容加密存储。
- 页面只快速提交并轮询状态，不把几分钟AI执行绑定在一个浏览器HTTP请求上。会话等待用户时停止高频轮询并释放worker。
- 同一用户关闭页面后能恢复原会话；完整结果恢复及采用新回复时核对版本与配对原图，不能用旧缓存图片拼接另一次的答案；人工草稿不随新回复自动覆盖。

这些措施减少无谓等待和重复工作，但两阶段不可能保证比单次转录更快。真实速度需用相同样本、清晰度、模型参数和输出要求做小样本对照，且同时检查几何条件是否完整。

## 辅助线与派生图片

几何辅助线采用独立队列任务。解题结果或用户明确要求后，模型先返回受约束的构造计划，再由服务端校验点名、依赖和退化情况，编译成有限的GeoGebra命令，同时复用已校验坐标显示无需联网的本地SVG示意图；外部GeoGebra按需打开，失败不影响本地图。用户可逐步预览、回看和保存；计划绑定当前题目、答案和解析版本，过期计划必须重新生成。

若管理员单独启用Gemini图片编辑模型，用户确认构造计划后才可生成带辅助线的派生图片。原图只读且不会被覆盖，服务端会限制图片格式/大小、重新解码并过滤非图片响应。普通多模态识图模型不自动获得图片编辑权限。详细边界见[几何辅助线与图片编辑](ai-drawing.md)。
## 教学结果与展示边界

解题仍输出严格JSON状态协议，不恢复旧XML外层。旧版教学要求已迁入新协议：题干、参考答案、解析、错误作答和错因分别存储Markdown正文；解析包含解题思路、分步解答、检验与总结，小问分别对应，表格和LaTeX完整保留。识图转录还需把学生作答与题设分开，供纯文字模型有依据地分析错因。

题干、答案和解析默认预览公式与排版，源码按需展开；完整编辑器自动出现，作答状态、错误作答和错因可直接输入，知识点可增删，题图、保存及GeoGebra保留。预览和编辑不增加AI调用，动态演示仍需用户点击生成。排版修复也保护LaTeX命令，不把`\neq`、`\nu`、`\nabla`误替换为换行。

恢复教学细节可能增加输出长度，因此不承诺与纯识字等耗时；正常识图/解题调用次数、两条顺序、补读上限、队列及费用边界不变。历史简短解析不会自动重新生成。

## 兼容与验收

管理界面分两种任务顺序，模型能力仍单独声明。映射保留既有`text`/`vision`成员，portable-ai-config v1不变；ScanDex、ImgToDoc、本机统一搜索和家庭健康服务本轮不改。

合成测试覆盖Responses结束事件、纯文字与多模态路由、4次回查、原质量补读、人工暂停/恢复、原模型停用、预算、故障恢复、权限及图文取回。隔离浏览器只用合成账户/数据库，禁用真实worker；后台编排由模拟上游的SQLite集成测试验证。未外发用户题图或调用真实AI，不能据此宣称数学正确率和真实耗时已达标。

同题会话、轮数与数据边界见[多轮问答与人工澄清](ai-dialogue-roadmap.md)；辅助线和可选图片编辑见[几何辅助线与图片编辑](ai-drawing.md)。

最低必要知识、旧新提示词及上传压缩/原质量补读的对照见[旧版对照与直接编辑](notebook-editing.md)。


## 2026-09-25：识图失败兼容与安全诊断

两类错误不能混为模型不可用：`AI_RESPONSE_ERROR`表示未得到符合协议的可用结果，可来自接口外层、空正文、JSON语法或字段校验；`AI_ACCEPTANCE_UNKNOWN`表示无法确定服务端完成状态，不能自动重发。单次调用仍最多180秒，并受剩余轮次活动时间约束，不通过延长等待或重置预算隐藏问题。

- 当时的JSON入口（已由下方2026-10-05受限兼容扩展）仅清理开头已闭合的`<think>...</think>`与外层代码围栏。不从未闭合思考块提取猜测，不任意截取正文，也不自动修补LaTeX反斜杠、角名或题目关系。
- 存储用`GeometrySchema`保持严格。只有AI转录入口把不可用的可选裁剪区域丢弃；省略区域时回到完整原图核验，不额外重做整次转录。无效顶点/射线、退化角和重复角编号仍拒绝，不能变成已核验角。
- 接口明确报告输出截断时，即使正文看似可解析也不得当成完整答案；仅有思考字段时不能拿思考内容充当正文。结构异常不会把上游原始错误文本写进错误消息。
- 尝试记录的已有加密metadata增加可选固定原因码，无数据库迁移。页面只映射本地白名单中文说明；不保存原始响应、思考内容或自由文本异常信息。旧记录无法补出历史细分原因。
- 超时分为等待响应头与读取完整正文两个阶段；它们都保持unknown状态和禁止自动重发。只按明确的失败回退，保持租约、调用额度、取消和恢复边界。

本节前一次修复未更改各供应商的thinking参数、Chat流式开关或最大输出token（后续流式调整见下节），没有依据猜测强行关闭思考。ScanDex的Chat路径也使用非流式请求，不能把两者速度差简单归因于是否流式。同名模型不代表输入长度、图片和输出协议相同；真实失败还需新记录的诊断证据。此轮仅使用合成响应和隔离测试，不发送用户题图。

## 2026-09-25后续：转录契约与识图专用流式

- 修正识图示例中不合法的`source: "text或image"`，改用通过同一Schema校验的完整示例；几何字段说明与实际示例分开，避免把说明当作点名。辅助列表明确数量与长度限制。
- AI入口允许`facts`、`uncertainties`、`missingInformation`省略、null或空列表；单条文字辅助信息规范为列表，文本事实保留内容但不虚构来源。必须有非空题干，错误的编号角语义仍拒绝，不修补角名或数学关系。
- 仅`recognize`角色（初次识图、几何核对、视觉补读）的Chat/Azure请求设`stream:true`，正常JSON外层回包仍兼容；Responses原有流式及Gemini协议不变，解题模式不变。
- 收集正文增量，忽略思考增量；只有`finish_reason: stop`才接受。截断、过滤、空正文为明确失败；缺少明确完成帧或中途断流为未知，不自动重发。收到完成帧立即取消reader，避免继续等悬挂连接。
- 不加猜测的供应商thinking/temperature/max_tokens参数；不提高单次180秒、轮次活动时间、响应大小上限或调用预算。流式主要改善接收和诊断，若供应商仍不及时输出或生成超过预算，仍可能超时。
- 旧失败未保存原始响应，无法证明那次Qwen具体缺哪个字段；发现的提示词冲突已由合成回归复现。测试通过不等同真实题图识别正确，不自动重跑用户的未知任务。

## 2026-10-05：完整JSON与LaTeX转义兼容，开发防回归

`src/lib/ai-dialogue/json.ts`是模型正文的受限兼容层，`protocol.ts`负责大小上限、Schema校验和固定诊断。初次识图、定向补读、角标核对、解题及共用该入口的作图描述走同一路径。供应商外层仍由`ai/transport.ts`判定结束、截断或拒绝；不要拿思考片段、流式半包或未确认完成的正文去尝试恢复。

允许的格式兼容：
- 单个完整JSON对象或数组前后的非结构性说明，可带一个完整代码围栏；引号中的花括号、转义引号、LaTeX括号不会当作结构边界。
- 仅在闭合的`$...$`或`$$...$$`数学区内，为已知LaTeX命令补齐缺失的JSON反斜杠转义。已正确转义的命令、引号、Unicode、换行及反斜杠对不重复解码；完整字符串内的物理换行/制表符规范为JSON转义，正文内容不改。
- 公式处理必须在JSON解码前进行，而不是只在`JSON.parse`抛错时处理：漏转义的`\frac`、`\theta`、`\beta`、`\nu`、`\rho`可能被当成合法JSON控制转义，解析成功也会静默损坏公式。

不允许的猜测：
- 不补齐截断对象、数组或字符串，不猜未转义双引号，不修任意未知反斜杠，不在普通文本/路径内全局替换，不自动改用第二个JSON候选。
- 多个候选、未闭合思考块、歧义结构仍返回固定`JSON_INVALID`。Schema错误、无效角证据和上游截断继续分开报错；不放宽角号、顶点、射线和图示关系，不凭空添加题设。
- 不使用通用`jsonrepair`补造残缺字段，不发送额外收费AI请求修JSON，不保存原始模型回复、私有题干或自由格式错误。不能根据脱敏错误码宣称已回溯确定某次真实失败的唯一原因。

后续维护检查：
1. 结构化提示词的转义示例统一由`JSON.stringify`生成，复用`JSON_OUTPUT_RULES`；不要在普通模板字符串里手写易被JS吞掉的反斜杠示例。提示词仍要求严格JSON，兼容层不是放松模型协议。
2. 修改提示词、解析器、协议适配或流水线时，运行`src/__tests__/unit/ai-dialogue/json-ingress.test.ts`、`protocol-compat.test.ts`、`src/__tests__/integration/ai-dialogue.test.ts`及`src/__tests__/unit/ai-config/response-diagnostics.test.ts`；新问题先加脱敏合成失败样例再修代码。
3. 测试须同时断言公式逐字保真、首次识图和补读落库、无额外调用、正常JSON不重复转义、截断拒绝与角证据不放宽。不要把原本防题设被篡改的拒绝测试直接删掉。
4. 本地验证不自动重跑失败/未知的用户任务，也不重新识别旧题。原失败回复未保存，本轮合成回归不能替代用户对同一题目的真实验收。
## 2026-10-05：底图纠正重生成，开发防回归

- 第一阶段不能复用第二阶段的不可变坐标指令：此前共用的布局规则包含不能平移、缩放或改写原有点的坐标，与纠正请求冲突。共用规则只保留原图方向/题设保护；不可变坐标约束只用于第二阶段。第一步明确允许修改错误点位，不能以锁底为由保留上一版错误。新增独立提示词契约测试，既验证第一阶段可纠正，也验证第二阶段仍锁底。
- 第一阶段允许可选`drawingPreviousBase`，发送给模型为`previousBase`：仅作为被纠正的旧图对照，可修改，不是题设真源。原题、原图、人工纠正及已有角标核对仍是依据；不向第一阶段发送答案或解析。不得把旧图误装入第二阶段的`drawingPlan`/`lockedBase`，两个字段同时出现必须拒绝。
- `drawingPreviousBase`必须是无辅助steps的完整合法底图，HTTP受理及后台执行均校验几何引用。字段必须经JobInputSchema进入持久任务，不能只在前端临时附带后被Schema丢弃。非几何作图接口拒绝此字段。
- 每次手动再生成使用新的请求ID和任务；同请求ID的网络重发保持幂等。旧结果只用于等待时展示和纠正对照，不作为新任务的缓存命中；不自动追加收费重试。
- 点位/连线纠正必须落实到实际绘图字段，不能只改title/notes；提示词不为制造差异而随意移动本来正确的点。结果比较忽略标题、图注、数组顺序、线段端点方向和可选空数组；相同绘图内容明确提示，不能统称已纠正完成。此检查不判断数学正确性，也不把图注变更本身判为无用。
- 进度条、任务受理链接及反馈紧跟实际触发按钮；从图下纠正按钮发起时，不能把进度放回被大图隔开的第一步顶部。它是等待指示，不是真实完成百分比。失败保留旧图并停止进度；成功替换SVG但不自动勾选锁定；生成期间再改纠正文字，旧请求返回仍须标作过期。
- 防回归覆盖`drawing-regeneration*.test.*`和持久任务集成测试：旧底图传递/落库、第一阶段不泄入答案/lockedBase、实际SVG变化、仅图注变化提示、就近进度、失败保留、在途修改、所有权、请求幂等与手动新任务、无隐式收费调用。保留两阶段锁底及JSON/角证据既有用例。
- 排查没有读取真实失败题目或模型回复，不能据合成测试断言某次历史失败的唯一原因，也不能承诺AI每次纠正都准确。


## 阅读与分享的图注归属防回归（2026-10-05）

- 真源不变：`notes/annotations`仍属于锁定原题底图；第二步仅新增`steps`，辅助线专属说明取结构化`steps.description`，不靠关键词猜测哪条题设属于辅助线，不把推导写成原题条件。
- `SolutionDocument`先取得实际勾选且有效的第一步图注；第二步仅过滤与之完全一致的展示行（包括confirmed/uncertain状态），保留独有说明及不同状态的条件。未勾第一步时必须完整显示第二步图注，切换立即恢复，不删除持久化notes。
